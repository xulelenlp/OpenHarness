# 先对齐再执行与选项式澄清验收案例

本文是「任务执行前/执行中遇到不明确点时，先给选项让用户确认，再继续执行」的验收清单。
重点覆盖三类任务：**分析报告、上传文档分析总结、指标口径查询**；验证的是现有
`ask_user_question` 工具 + 审批事件通道，不是一套新的计划模式。

## 3. 手动验收案例

### 案例 A：确定性的单问题闭环（推荐先跑）

输入：

```text
我在做前端验收：请先用 ask_user_question 就“报告聚焦哪个分析维度”给我 3 个选项
（含一个推荐项）；等我确认后，只回复一句“已收到：<我的选择>”，
不要调用其他工具、不要生成文件。
```

预期：

1. 执行轨迹出现 `ask_user_question`，状态为「等待回答」；下方出现「需要你确认」问题卡。
2. 问题卡展示 3 个选项 +「其他（自行输入）」，至少一个带「推荐」；「确认并继续」在未选择前禁用。
3. 顶栏与输入区出现「等待确认」，输入框占位为「请先回答上方的问题…」。
4. 选择第一项 →「确认并继续」→ 卡片变为「已确认：<选项>」，工具步骤完成。
5. 模型只回复「已收到：<选项>」，不再调用工具；任务结束。
6. 刷新页面后，问题仍是「已确认」完成态，不会重新出现按钮。

### 案例 B：隐式触发（验证模型行为）

输入：

```text
帮我做一份售电量分析报告，信息不足的地方先问我。
```

预期：模型在统计范围 / 分析维度 / 输出格式等关键点上调用 `ask_user_question`，给出
2–4 个具体选项；用户确认后继续取数与生成报告。模型如果直接给合理默认值并说明，也属于
可接受行为；本案例用于观察模型倾向，不作为硬性断言。

### 案例 C：「其他」自由输入

在问题卡选择「其他（自行输入）」，输入：

```text
按日粒度，最近 7 天，只要 Markdown，不要 Word
```

确认后预期：

- 卡片显示「已确认：按日粒度，最近 7 天，只要 Markdown，不要 Word」；
- 工具结果原样带回该文本；模型按该口径继续；
- 「其他」为空时按钮保持禁用。

### 案例 D：连续多个问题

使用真实报告类 prompt（例如案例 B）。模型可能在「统计范围 → 分析维度 → 输出格式」
上连续提问。每回答一个，下一张问题卡继续出现；全部确认后任务才继续执行。
输入区在任一问题等待期间都保持禁用发送。

### 案例 E：待确认时刷新

问题卡出现后直接刷新页面。预期：

- 会话恢复后问题卡与选项重新出现，仍可作答；
- 作答后任务继续（原 SSE 连接由后端保持；若后端已结束进程则按超时/中断处理）。

### 案例 F：回答后刷新

回答问题并等任务结束后刷新。预期：

- 原位置显示「已确认：<答案>」，不再有 radio/按钮；
- 执行轨迹、附件、文件卡、最终回答完整。

### 案例 G：权限 / 编辑审批回归

触发一次 `run_script` 或需要确认的工具：

- 「允许 / 总是允许 / 拒绝」三态正常；
- 权限卡可展开工具参数；编辑审批可看到 diff；
- 处理结果写入轨迹，刷新后不重复弹出；
- 问题卡的 `approval_resolved` 不影响权限审批原有语义。

### 案例 H：纯文本问题

如果模型调用 `ask_user_question` 但不带 `options`：

- 卡片显示问题正文 + 单行输入 +「确认并继续」；
- 提交后答案回传，任务继续；
- 不出现空白选项区或错误。

### 案例 I：分析报告开工对齐

输入：

```text
帮我做一份 2026 年 9 月福建售电量分析报告。
```

预期：

1. 若期间/口径/交付物有缺失或多解，模型调用 `ask_user_question`（一张「任务简报」卡或针对缺失点的问题），给 2–4 个选项并标推荐项。
2. 问题为单行，能看清已推断的主题/期间/口径/交付物；详细差异放在选项 `description`。
3. 用户选择后，模型按该口径取数并生成报告，不再重复问同一点。
4. 报告开头或附录写清实际采用的期间、口径、机构层级、单位。
5. 用户明确说「直接写，别问」时，模型不提问，说明默认口径后直接执行。

### 案例 J：上传 Excel/Word/TXT 的深入分析与总结

上传一个含 2 个工作表的 Excel，并输入：

```text
帮我深入分析这份材料，做个总结。
```

预期：

1. 模型先盘点附件（工作表名、行数、解析状态、覆盖范围），而不是只读 1500 字预览。
2. 只对缺失的「分析目标/范围/输出」提问，给 2–4 个选项；确认后不重复问。
3. 产出包含一句话结论、关键发现、数据与口径核验、问题/风险、建议，并标注来源（工作表/单元格/章节）。
4. 解析失败或内容截断时，明确说明覆盖范围，不假装读了全文。

### 案例 K：指标口径查询与多候选

输入：

```text
售电量是什么口径？
```

预期：

1. 模型调用 `db_query(operation="describe")`，回答包含单位、周期、机构层级、最新可用日期、定义/来源。
2. 若 `describe` 返回多个候选或 `needs_confirmation`，模型用 `ask_user_question` 列出 2–4 个候选让用户选，不擅自选。
3. 用户在「其他」里输入自定义指标时，模型按新指标重新解析，不沿用旧口径。

### 案例 L：不该问的场景

输入：

```text
查一下厦门 2026 年 9 月售电量。
```

预期：参数齐全，模型直接 `db_query`，不出现选项卡。

输入：

```text
按你的判断做一份售电量简报，别问。
```

预期：模型不提问，说明默认期间/口径后执行；不因「对齐协议」强行加一轮确认。

## 4. 视觉验收

在 1440、768、390 三档检查：

- 空状态：品牌标识、标题、示例问题卡、输入区不溢出；
- 对话中：用户气泡右对齐、助手正文可读、执行轨迹紧凑；
- 待确认：问题卡完整可见，选项可点击，底部「确认并继续」不被输入区遮挡；
- 移动端：侧边栏默认隐藏，汉堡按钮可打开；文件抽屉为覆盖层；选项文字换行不破版；
- 刷新/切换会话：无横向滚动、无按钮重复、无「思考中…」卡在等待确认状态。

## 5. 排障

| 现象 | 检查 |
| --- | --- |
| 模型一直文字追问，不出选项卡 | 看该 Agent 的 `tools` 是否包含 `ask_user_question`；看系统提示/能力清单是否加载；用案例 A 的显式 prompt 区分「模型没调工具」与「链路问题」 |
| 有 `tool_started` 但没有问题卡 | 浏览器控制台看 `[sse]` 是否收到 `approval_required`；后端日志看 `sse emit`；检查 SSE 分帧 |
| 点击确认后卡片不消失 | 看 `POST /approvals/{request_id}` 是否 200；看是否收到 `approval_resolved`；检查是否重复提交 |
| 刷新后问题又变成待处理 | 确认轨迹里有 `approval_resolved`；旧会话没有该事件时属于预期（只对新版本产生的轨迹生效） |
| 选项显示不全 | 服务端最多接受 6 个；前端会过滤空 label / 重复 label；检查 `payload.options` |
| 审批超时 | 默认 300s；超时后发 `approval_resolved(timeout)`，问题返回空串 |
| 模型问太多 | 检查能力清单是否加载「不该问的」；确认用户是否已给全参数；看是否把「任务简报」拆成多次提问；确认没有对已确认的点重复问 |
| 该问不问 | 检查 `tools` 是否包含 `ask_user_question`；看系统提示/能力清单是否加载；如果存在唯一明显默认值，不问属于正常 |
| 口径查询没有候选提示 | 看 `db_query describe` 输出是否含 `candidates` / `needs_confirmation` / `notes`；旧版本没有这些字段 |
| 口径回答缺单位/周期 | 确认是否先用了 `describe`；是否只调了外部智能体而没有核验元数据 |
